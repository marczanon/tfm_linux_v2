\chapter{Introducción}

\section{Contexto}

La detección de anomalías en maquinaria industrial es una tarea relevante para
mejorar la fiabilidad, reducir paradas no planificadas y apoyar estrategias de
mantenimiento predictivo. En sistemas rotativos, como motores eléctricos,
turbinas, bombas o rodamientos, las señales de vibración permiten observar
cambios de comportamiento asociados a desgaste, desbalanceo, defectos mecánicos
o degradación progresiva.

Este trabajo se centra inicialmente en rodamientos de motores eléctricos, usando
como dataset principal CWRU Bearing Dataset \cite{cwru_bearing_data_center}. El
dataset NASA IMS Bearing se conserva como fuente futura para validar escenarios
de degradación run-to-failure \cite{nasa_pcoe_repository}.

\section{Motivacion}

El interés del proyecto no se limita a entrenar un modelo de detección de
anomalías. El objetivo es construir una arquitectura capaz de coordinar el flujo
completo de datos: ingestión, perfilado, limpieza, estructuración temporal,
entrenamiento, evaluación, auditoría e informe técnico. Para evitar
transformaciones opacas o no reproducibles, los agentes proponen decisiones
estructuradas y los ejecutores deterministas aplican las operaciones reales.

\section{Problema}

El problema abordado es la detección automática de patrones anómalos en señales
de vibración procedentes de rodamientos. En el MVP se formulará como una tarea
binaria:

\begin{itemize}
  \item clase normal: operación sin fallo;
  \item clase anómala: cualquier fallo de rodamiento disponible en el dataset.
\end{itemize}

La clasificación por tipo de fallo se mantiene como extensión posterior. Esta
decisión reduce el alcance inicial y permite validar primero la trazabilidad del
pipeline multiagente.

\section{Objetivo general}

Diseñar e implementar una arquitectura multiagente basada en LangGraph para
procesar datos industriales de vibración y detectar anomalías de forma
reproducible, auditable y extensible.

\section{Objetivos específicos}

\begin{enumerate}
  \item Definir una estructura de proyecto que separe código, memoria académica
        y recursos.
  \item Seleccionar un caso de uso industrial y datasets públicos adecuados.
  \item Diseñar un pipeline de datos reproducible para señales de vibración.
  \item Definir contratos estructurados para agentes y ejecutores.
  \item Implementar ejecutores deterministas para perfilado, limpieza,
        estructuración temporal, modelado y evaluación.
  \item Construir un MVP local antes de abordar Docker, SLURM o frontend.
  \item Generar informes técnicos trazables a partir de métricas y artefactos.
\end{enumerate}

\section{Alcance y limitaciones iniciales}

El alcance inicial queda limitado a ejecución local, ficheros crudos en disco y
un dataset principal. No se abordarán en el MVP la ejecución distribuida,
streaming industrial, integración SLURM, frontend ni persistencia avanzada. NASA
IMS se mantiene como extensión experimental una vez validado el flujo sobre
CWRU.
